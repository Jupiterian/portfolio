# Sprint 1 Onboarding Challenge — Reflection

**Challenge:** [Onboarding Challenge — Ground 0](https://pages.opencodingsociety.com/sprint1/challenge/csp/)

## Overview

Sprint 1 was about getting a real development environment stood up and learning the workflow that everything else this year will run on: VS Code plus extensions, Make for automation, Git for history, and GitHub / GitHub Actions / GitHub Pages for publishing. By the end of the sprint I had a working local setup, a published portfolio site, and a repeatable commit-and-push routine. The reflection below rates where I currently sit on each area, with evidence.

**Evidence**

- **T05 — Tools & Equipment Hacks (3):** Completed the assigned tools hacks — used `make` targets to automate the build/serve loop and customized a couple of small scripts. I can use these independently in project work, but I have not yet written my own automation from scratch, so this is an Apply-level 3.
- **T06 — Portfolio / Blogging Hacks (4):** Created and published multiple Markdown pages on my portfolio, including this reflection and issue-template content. I can structure a page with headings, tables, links, and code blocks, and I fix rendering problems by previewing locally before pushing. - **T07 — Theme / Style / Layout (3):** Made theme and layout edits — changed styling values, adjusted navigation, and modified page layout components. In [Open-Coding-Society/pages PR #1377](https://github.com/Open-Coding-Society/pages/pull/1377), I added a new drag-and-drop button CSS variant (`variant-dragdrop.scss`), wired it into the shared button import chain, and documented the class/state grammar used by the UI. I also verified responsive behavior at mobile and desktop widths, which is direct evidence that I can implement and test real CSS component changes, even though larger full-theme restructures still take me trial and error.
- **T08 — JavaScript / Coding Challenges (4):** Completed the JavaScript coding challenges, working with variables, functions, loops, arrays, and DOM output. When a challenge failed I used `console.log` and the browser dev tools to trace the bug and compare approaches before settling on a solution. I can work independently and debug my own code.
- **T09 — AI Orchestration (4):** Used AI tools as part of my workflow to scaffold code, explain errors, and draft content, then reviewed and edited the output rather than pasting it blindly. I can judge when an AI answer is wrong and correct it, and I use it to move faster without losing understanding of what my code does.
